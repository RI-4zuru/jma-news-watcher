# JMA News Watcher v4 — 気象・防災ニュース監視

気象庁業務に関係する火災・水難・地震・黄砂・河川氾濫・土砂災害・竜巻・降雹・濃霧・霜・大雨・大雪・台風・落雷などの報道をGoogleニュースの検索RSSから収集し、地域別に表示する個人用ダッシュボードです。公的機関の公式情報の代用にはなりません。

## GitHub版（推奨）

- `.github/workflows/news.yml` が定期的に `collect.py` を起動します。定期実行の指定は5分間隔ですが、実行遅延やスキップの可能性があります。
- `site` フォルダを GitHub Pages に公開します。サイト画面は自動的に60秒ごとに `site/data.js` を確認します。
- `Actions → Collect and publish weather news → Run workflow` で手動収集も可能です。
- 既に v3 を公開している場合は [UPDATE-v4.md](UPDATE-v4.md) の更新手順を参照してください。
- 新規作成の場合は [GITHUB-SETUP.md](GITHUB-SETUP.md) を参照してください。

## ブラウザ表示・設定

- 上部：**すべて／重要／NEW 24h／★保存**、記事分類、表示期間、キーワード検索、**🔔新着通知**、**⚙設定**。
- **⚙設定 → 表示エリア**：1～6エリア、地域は47都道府県・地方区分・近畿地方・全国・全てなどから設定。各エリアの `↗ 別画面` リンクは従来どおり利用できます。
- **⚙設定 → デザイン**：システムの配色設定に合わせる、ライト、ダーク。ニュースの密度はコンパクト／標準。
- **⚙設定 → ニュース配信元**：すべて／主要メディアのみ／選択したメディアのみ。ニュースサイトのショートカットもあります。
- **⚙設定 → 新着通知の条件**：別ウィンドウの監視ON/OFF、対象地域（複数）、記事の公開日時（日本時間）の下限。ウィンドウ自体は上部の `🔔新着通知` ボタンで開きます。
- NEWは**記事の公開時刻から24時間以内**のみ表示（60秒ごとの画面確認で更新）。初回取得された記事がすべてNEWになるわけではありません。
- 設定、保存済み記事は同じブラウザのlocalStorageに保存されます。ブラウザデータ消去や他の端末には引き継がれません。
- CSV出力・一括既読・手動更新・ブラウザ通知ボタンは廃止しました。記事を保存する★は残しています。

### 配信元に関する制限

現在のニュース収集はGoogleニュースRSSの検索結果です。`source`には通常発行元の新聞社・放送局名などが記載され、Yahoo!ニュースに転載された記事でも「Yahoo!ニュース」にならない場合があります。**配信元フィルタは収集済み記事の表示を絞る機能**であり、各社の記事を直接スクレイピングしているわけではありません。媒体の選択は通知ウィンドウにも反映しますが、TelegramのGitHub側通知条件は従来のままです。

## ローカル（Windows）

- `update.cmd` でニュースを収集し、`site/index.html` をブラウザで開きます。
- `start-monitor.cmd` はローカル収集を繰り返します。WindowsのPowerShell 5.1環境では `collect.ps1` のUTF-8 BOMが必要です。
- GitHub版を利用している場合、Windows側の収集は不要です。

## データ保持・安全

- `config.json` で対象分野、過去7日保存、収集件数上限などを定義します。
- GoogleニュースRSS取得エラー時、以前の記事は残します。
- 地域・内容・ニュース媒体はタイトル中心に推定するため誤判定や漏れがあります。
- GitHub Pages は通常公開サイトなので、個人情報やトークンを入れないでください。TelegramのトークンはGitHub Actions Secretsに保存します。
- ニュースの取得・ブラウザの画面表示・通知はネットワーク条件、ブラウザ制約、GitHub側の都合で遅延・欠落し得ます。
